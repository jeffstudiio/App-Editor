## ۱) مدل داده — ترنزیشن روی نقطهٔ تدوین (Edit-Point Model)

مرجع حقیقت: `src/lib/video/types.ts`

```ts
interface TimelineTransition {
  id: string;
  leftClipId: string;   // کلیپ سمت چپ مرز
  rightClipId: string;  // کلیپ سمت راست مرز (باید دقیقاً بعد از left در آرایه باشد)
  type: TransitionType; // ۱۲ خانوادهٔ واقعی
  dur: number;          // clamp به نصف طول هر همسایه، سقف مطلق ۱.۵s
  direction?: "left" | "right" | "up" | "down";
  easing?: "linear" | "smooth" | "snap";
  intensity?: number;   // 0.1..1
  tint?: "warm" | "gold" | "cool";  // برای lightLeak
  preset?: string;      // id کارت مرورگر (خانواده‌های بیوتی = پریست پارامتری)
}

interface Project {
  clips: Clip[];
  transitions: TimelineTransition[];  // ← ترنزیشن اینجاست، نه روی کلیپ و نه روی کل تایم‌لاین
  overlays, texts, audios, markers, aspect, schemaVersion(3)
}
```

**نسبت معنایی (طبق §8 مشخصات):** `Transition = property of the boundary between Clip A and Clip B` — ترنزیشن هرگز ویژگیِ «ورودی یک کلیپ» یا «کل تایم‌لاین» نیست.

**ثابت‌های اجباری که هیچ مسیری نمی‌تواند بشکند:**
- `cleanupTransitions(p)` داخل `mutate` ادیتور و بعد از هر عمل Agent اجرا می‌شود:
  ترنزیشنی که کلیپ‌هایش دیگر مجاور نیستند حذف می‌شود؛ `dur` به `maxBoundaryDur` clamp می‌شود.
- `maxBoundaryDur(durLeft, durRight) = min(1.5, durLeft×0.5, durRight×0.5)` (§12 — محدود به طول همسایه‌ها).
- مایگریشن: پروژه‌های قدیمی (schemaVersion ≤2 با `clip.transitionIn`) در `normalizeProject`
  خودکار به مدل مرزی تبدیل می‌شوند (شامل alias ‏`black→dipBlack`)؛ ترنزیشنِ کلیپ i یعنی مرز (i-1|i).

## ۲) موتور رندر — ۱۲ خانوادهٔ واقعاً متمایز

`src/lib/video/engine.ts` — یک مسیر مشترک `drawFrame` برای پیش‌نمایش، MediaRecorder و WebCodecs.

- **زیرِ لایه (Frozen-tail underlay):** در پنجرهٔ ترنزیشن، آخرین فریم کلیپ قبلی زیر افکت کشیده می‌شود؛
  بنابراین «دیسالو» واقعاً cross-dissolve است (قبلاً محوِ روی سیاهی بود).
- `drawBoundaryTransition(ctx, prev, act, tr, t, W, H)`: پیشرفت `q = local/dur` → easing (`trEase`) → افکت.
- خانواده‌ها: `fade` (دیسالو متقاطع) · `dipBlack/dipWhite` (عبور از سیاهی/سفیدی با سینوسی) ·
  `slide` (ورود از جهت) · `push` (قبلی را بیرون می‌راند) · `zoom` · `blur` · `wipe` (clip-rect لبه‌ای) ·
  `flash` (برش سخت در میانه + برق سفید) · `spin` (چرخش+مقیاس) · `glitch` (اسلایس‌های قطعی با jitter
  بدون Math.random تا پیش‌نمایش = خروجی) · `lightLeak` (موج نور گرادیانی با composite «screen» و tint).
- افکت از طریق `FxState {alphaMul, dxMul, dyMul, scaleMul, rotAdd, blurAdd}` به `drawClip` تزریق می‌شود؛
  مسیرهای قدیمی `transitionIn` از موتور حذف شده‌اند.

## ۳) برش واقعی (§6) — منبع واحد

`splitClipAt(clips, index, srcSplit, makeId)` در `src/lib/video/edit-ops.ts` — **تنها** مسیر برش
(UI، Agent، split-at-markers، inجِ لایه به ترک اصلی همه از همین استفاده می‌کنند):

- نیمهٔ چپ همان `id` را نگه می‌دارد → ترنزیشن چسبیده به مرز (قبلی|کلیپ) خودش سرِ جایش می‌ماند؛
  مرز تازهٔ (A|B) تمیز است.
- منبع/تایمینگ/ترنسفورم/فیلتر/ماسک/کراپ/صدا در هر دو نیمه حفظ می‌شود.
- کی‌فریم‌ها با `splitKeyframeMap(kf, localSplit)` با **پیوستگی** شکسته می‌شوند:
  کلید مصنوعیِ لحظهٔ برش برای A و کلید مصنوعیِ صفر برای B.
- بعد از برش: کلیپ راست انتخاب می‌شود، پلی‌هد روی نقطهٔ تدوین می‌ماند و لبهٔ جدید pulse می‌گیرد.

## ۴) انتخاب (Selection Model §5)

`Selection = { type: "clip" | "overlay" | "text" | "audio" | "transition", id }`

- ضلع الماس (edit-point) بین دو کلیپ → اگر ترنزیشن دارد: انتخابش می‌کند و پلی‌هد به وسطِ
  پنجرهٔ ترنزیشن می‌رود؛ اگر ندارد: مرورگر ترنزیشن روی همان مرز باز می‌شود (§9 دقیقاً).
- نوار ابزار کاملاً بافتاری است: کلیپ → [برش، ترنزیشن، پریست‌ها، افکت‌ها، سرعت/صدا، …]؛
  ترنزیشن → [تغییر نوع، مدت، جهت، حذف]؛ متن/لایه/صدا مجموعهٔ خودشان.
- Delete/واگرد روی هر انتخاب (از جمله ترنزیشن) کار می‌کند؛ حذف کلیپ مرزهایش را هم تمیز می‌کند.

## ۵) چیدمان Workspace (§3-§4، §17) — پنل هرگز تمام‌صفحه نیست

- **موبایل:** ستونِ `پیش‌نمایش (flex) → ترنسپورت → نوار ابزار بافتاری → تایم‌لاین (shrink-0) → ToolDock`.
  ToolDock یک پنل **داخلی** با حداکثر `min(46dvh, 430px)` است — باز شدنش ترنسپورت و نوار ابزار را
  مخفی و پیش‌نمایش را کوچک می‌کند ولی **پیش‌نمایش و تایم‌لاین هرگز کاملاً پوشیده نمی‌شوند**.
- **دسکتاپ (≥1024px):** `پیش‌نمایش+تایم‌لاین (چپ) | Inspector (راست، 340px)` — ابزارها به‌صورت
  چیپ‌های wrap و محتوای پنل داخل Inspector؛ پیش‌نمایش همیشه کامل.
- ورود رسانه/پنل‌ها دیگر `Sheet` مودال 88dvh نیستند؛ مودالِ تمام‌صفحه فقط برای busy overlay.

## ۶) تایم‌لاین (§14-§16)

- زوم: دکمه‌های +/− و **پینچ دو‌انگشتی** با لنگرِ مرکز پینچ؛ بازهٔ 18..160 px/s.
- دستگیرهٔ الماسی نقطهٔ تدوین بین هر دو کلیپ مجاور + **نوار ترنزیشن** (پهنای `dur`، برچسب نام) روی
  نیمهٔ راست — ترنزیشن روی تایم‌لاین **دیده می‌شود**.
- اسکراب/تریم/درگ/اسنپ/ریپل از قبل واقعی‌اند و با `pxs` زوم کار می‌کنند.
- پیش‌نمایش همیشه دنبال پلی‌هد است؛ هر تغییر (split/ترنزیشن/فیلتر/متن) فوراً در canvas دیده می‌شود.

## ۷) مرورگرها و پریست‌ها (§10، §23-§26)

- `TransitionBrowser`: پیش‌نمایش زندهٔ **واقعی** (EditorEngine دوم روی همان پروژه/رسانه‌ها و حلقهٔ
  زمانی پیرامون مرز، با درفتِ فعلی حتی قبل از اعمال) + ۱۷ کارت در ۴ دسته (پایه/حرکتی/استایلیش/بیوتی)
  + جست‌وجو + علاقه‌مندی + «اخیراً استفاده‌شده» (localStorage) + چیپ‌های مدت (0.1..1s، clamp زنده) +
  جهت + نرمی حرکت + حذف. اعمال = `setBoundaryTransition` روی همان مرز؛ بقیهٔ مرزها دست‌نخورده.
- `presets.ts` (رجیستری، نه موتور): ۶ پریست متن، ۱۳ پریست رنگ (خانوادهٔ بیوتی: بیوتی نرم، طلای لوکس،
  سالن تمیز، پوست گرم، جزئیات مو، محصول پرمیوم، ادیتوریال مین)، ۱۲ پریست انیمیشن (متن: TextAnim؛
  کلیپ: موشن کی‌فریمیِ همان `motionTransform` بانک — منبع واحد).
- `PresetsBrowser` فقط روی **آبجکت انتخاب‌شده** اعمال می‌کند؛ `EffectsBrowser` فقط ماژول‌های واقعی
  (نور/رنگ، وینیت/بلور/سپیا، کیفیت+، لرزش‌گیر، کراپ، ماسک، کروما) — هیچ افکت فیک‌نیمی در فهرست نیست.

## ۸) قالب‌ها (§18-§22)

- قالب‌های بانک (87 قالب JSON) از قبل «پروژهٔ قابل ویرایش» واقعی‌اند (بازسازی در `bank-apply` با
  اسلات/موشن/متن/موزیک) — حالا ترنزیشن صحنه‌ها هم به‌صورت **ترنزیشن مرزی واقعی** ساخته می‌شود
  (`TRANS_MAP` جدید: whip→push، spinTr→spin، glitchTr→glitch، filmBurn→lightLeak، …).
- `applyTemplateToProject` ترنزیشن قالب را روی همهٔ مرزهای داخلی می‌گذارد (یا با `null` همه را پاک می‌کند).

## ۹) هوش مصنوعی (§32-§33)

- Agent از **همان دستورهای ساختاریافته** استفاده می‌کند و مثل کاربر از `cleanupTransitions` عبور می‌کند:
  `add_transition` با `target:"clip"` فقط به مرزِ ورودیِ همان کلیپ می‌چسبد (رد صادقانه برای کلیپ اول)؛
  `target:"all"` به همهٔ مرزهای داخلی، هرکدام مستقل.
- فرمان‌های جدید: `set_transition_duration`، `remove_transition` (فقط همان مرز).
- `split_clip` حالا از `splitClipAt` استفاده می‌کند → کی‌فریم/ترنزیشن درست می‌شکند.
- هیچ مسیری از AI مستقیماً state فرانت‌اند را تغییر نمی‌دهد؛ همه‌چیز Edit Plan → Executor → Project.
